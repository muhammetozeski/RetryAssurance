# Concise project handoff

Read this method once when taking over. Select records by filename first; read the newest current context and the newest relevant synthesis, then only later records that affect this task. Do not read the entire archive or reconstruct it from Git. Stop once the task's context is understood.

Write a new file for a meaningful state change or learned result, using the actual local time as `yyyy.MM.dd HH.mm.ss - Descriptive outcome.md`. Explain current context, the evidence that changed the approach, the result and its meaning for continuation. Keep it short and link detailed reusable knowledge in docs. Do not copy file inventories, raw outputs or the entire task history.

Old records remain intact. Correct a mistaken conclusion explicitly in a new record; an optional dated correction can point forward from an already-known old record. Create a new synthesis only when it reduces repeated reading while preserving the reasons for decisions. The goal of minimal reading applies to these handoffs, not as a reason to skip required implementation or verification.
