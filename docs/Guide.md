# Documentation method

This library preserves project-specific knowledge needed to operate and change Retry Assurance without rediscovering tested behavior. Read the index and follow only relevant topics. Record the implemented contract, its reasoning, prerequisites, observed result and limits. A source inspection is not an executed request or browser result.

Use concrete subject names and link new topics from the nearest index. Update the actual source of outdated information instead of copying the same rule into several documents. General tutorials, speculative market claims, task plans and raw terminal logs do not belong here. Keep README focused on use and deployment, AGENTS focused on navigation, and dated handoffs focused on why continuation should change.

Only claim successful publication, signed billing or client verification after observing that outcome. A proposed price or workflow remains a hypothesis until tested. Before delivery, check links in changed documents and ensure the next developer can find the relevant prerequisite from the index.
